# NovaRelay 项目讲解指南

这份文档用于准备演示和技术讨论，不提供虚构指标。面试时只陈述自己实际完成、能够解释并可现场验证的部分。

## 30 秒介绍

NovaRelay 是一个面向客服与运营流程的可观测多智能体运行时。它把意图识别、RAG、专业 Agent 路由、分层记忆、动态 Skills 和质量评测串成闭环。重点不是再做一个聊天界面，而是解决 Agent 上线后的路由正确性、工具安全、质量回归和故障降级问题。

## 推荐演示顺序

1. 打开 `/docs`，展示公开 API 契约。
2. 用技术故障、重复扣款和转人工三个请求展示不同路由。
3. 打开 `/trace/tools`，说明工具白名单与调用轨迹。
4. 运行 `python -m evaluation.run_harness`，展示场景断言和质量门禁。
5. 修改一个阈值或模拟错误，展示失败隔离与非零退出码。
6. 说明 baseline 只有显式 `--promote` 才会更新，避免“测试后自动改答案”。

## 三个值得深入讲的设计

### 1. 为什么要把执行器和评分器解耦

`EvaluationHarness` 只依赖一个异步执行器协议。线上可以接真实 Orchestrator，单元测试可以接确定性 Fake。这样指标聚合、门禁和报告生成能够离线验证，不会把模型随机性混进框架测试。

### 2. 为什么 baseline 不能每次覆盖

候选版本和已批准基线是两个状态。普通运行只生成报告；成功运行仍需显式 `--promote`。这让回归比较有稳定参照，也便于接入代码评审流程。

### 3. 如何处理部分失败

每个 case 独立捕获异常。某一次模型超时不会终止整个 suite，而是进入 `error_rate` 并保留其它用例结果。线上故障因此能被量化，而不是只看到一段堆栈。

## 诚实回答边界

- 如果没有真实流量，不把离线样本结果称为“生产准确率”。
- 如果没有压测，不宣称 QPS 或并发容量。
- 如果功能来自原始代码，要能区分原有模块和自己新增、重构的部分。
- 指标一律附运行环境、数据集版本和报告文件。
